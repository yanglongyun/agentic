重写登录接口的重试逻辑 ~/work/agentic 浏览器

登录接口在弱网下偶发 401 之后就直接失败了，帮我加上指数退避重试，最多 3 次，网络错误也要重试。

好的，我先看一下现有登录请求的实现，再决定重试逻辑挂在哪一层。

TypeScript src/api/login.ts 
export async function login(payload: LoginPayload) {
  const res = await api.post('/auth/login', payload);
  // 目前没有任何重试，401 / 断网直接抛出
  return res.data;
}

现状确认：登录请求裸调 api.post，任何失败都会直接抛给 UI。我把重试收敛到一个 loginWithRetry 里，只重试「值得重试」的错误：

改动要点

  • 重试条件：HTTP 401（令牌刷新竞态）与网络层错误（ECONNRESET、超时），4xx 业务错误不重试。
  • 退避策略：基数 500ms 指数退避 + ≤120ms 随机抖动，避免弱网恢复瞬间的羊群效应。
  • 上限：最多重试 3 次，耗尽后抛出最后一次的原始错误，调用方感知不变。
JavaScript src/api/login.ts · 新增 
async function loginWithRetry(payload, { maxRetries = 3 } = {}) {
  let attempt = 0;
  const baseDelay = 500;

  for (;;) {
    try {
      return await api.post('/auth/login', payload);
    } catch (err) {
      const retriable =
        err.status === 401 ||
        err.code === 'ECONNRESET' ||
        err.code === 'ETIMEDOUT';
      if (!retriable || attempt >= maxRetries) throw err;

      const jitter = Math.random() * 120;
      await sleep(baseDelay * 2 ** attempt + jitter);
      attempt += 1;
    }
  }
}
